Two ways to use nimo

However the bug reaches you, nimo takes it from there.

Reproduce

Bug report + APK

A customer sent you a bug report. Hand nimo the report and the APK — it drives the app, reproduces the exact issue, and returns a verified verdict with the step-by-step trace, screenshots, and the crash log. No more "works on my machine".

Discover

Just the APK

No bug report yet? Give nimo only the APK. It explores the app like a relentless QA engineer — every screen, every menu, every edge input — hunting for crashes on its own, and gets back to you with every bug it found, each with its trace and log.

Every corner. Systematically.

Free-roam exploring is a wander — the nimo pipeline works from the APK's own map: every activity launched directly, every deep link fired, every button and field exercised, login walls handled (including Google Sign-In), crashes deduped by stack fingerprint. You get honest coverage — visited 21 of 23 screens — with unreachable screens explained, not hidden.

Map

Static analysis

The manifest gives up every activity, intent filter, and deep link. That's the coverage denominator — no map, no thoroughness claim.

Enter

Login, handled

Test credentials, automatic throwaway sign-up, or Google Sign-In through a pre-authed emulator snapshot. What it can't pass, it reports — with the reason.

Sweep

BFS crawl + triage

Breadth-first over every screen and element, edge-case inputs in every field, logcat watched throughout. Optional JaCoCo code coverage via the VALOR-Droid toolchain.

How it works

Three inputs in, one trustworthy answer out.

Step 1

Drop in the bug — or just the app

Reproduce mode: hand nimo the APK and the bug report as plain markdown. Discover mode: just the APK — nimo explores and hunts on its own. That's the whole integration.

Step 2

The agent drives the app

nimo installs the app, reads the screen, and taps, types, and swipes its way through the report — reasoning about each screen like a QA engineer, powered by Pollinations AI (free, no key).

Step 3

Get a verdict

reproduced or not_reproduced — with the step-by-step trace, screenshots, and the logcat crash. Crash verdicts require a real FATAL EXCEPTION: the agent can't hallucinate a repro.
